# 業種特化指標（benchmark）の方針

出典: 旧課題管理のチケット（移行日 2026-11-12）。当時の題名: 業種特化指標（benchmark）の方針：有報から構造化。
方針の進捗はオーナー管理のトラッカー Sheet。実装面が要るときは GitHub Issue を立てる。
この文書は決定・契約の正本としてリポジトリで維持する。件数や進捗の最新値はここに書かない。

## 目的

業種ごとの特化指標（例：銀行の預貸率、自動車の生産台数実績、ハウスメーカーの着工棟数）を有報から構造化し、同業比較（benchmark）に使う。

## 方針（2026-11-02 決定）

* データ源は有報。XBRL の数値タグがあればそれを使う。
* 平文（本文や表）にしかない指標は、抽出したうえで Jev で正規化する（決定論的コード＋閉じた選択肢。確信度0.9未満は要レビューとする Fail-Closed）。
* 最初の業種は銀行。そのほかの業種も実装する価値と取りやすさを調べ、優先順位を決める。
* 基本は期末の数字を使う。利回りと利ざやだけは、開示が平均残高ベースなので平均を使う。
* 1社に複数の業種タグを付けられるようにする（例：ソニー、楽天、電鉄会社）。KPI の値ごとに、どのセグメントや子会社の数字かを持たせる。主にするタグはセグメントの売上の割合で決める。数値が取れるものだけ取り、無理に埋めない。上場子会社の数字は、その子会社の有報から取るほうを優先する。

## 銀行の対象指標（候補）

* 預金残高・譲渡性預金・貸出金残高とその利回り（利息も取得）。預貸金利ざや＝貸出金利回り−預金利回り
* 預貸率（LDR）＝貸出金 ÷（預金＋譲渡性預金）× 100（%）
* 経費率（OHR）＝営業経費 ÷ 連結粗利益 × 100
* 業種別貸出金
* 不良債権比率
* 規制上の自己資本比率

## 未決事項

* 国内業務部門と国際業務部門の扱い（合算するか、分けて持つか）
* ~~期末残高と平均残高のどちらを使うか~~ → 2026-11-02 決定：基本は期末の数字。利回り・利ざやだけは開示が平均残高ベースなので平均を使う。
* 連結と単体のどちらを使うか（持株会社の有報では傘下の銀行ごとに表が分かれる点も含む）
* 業種別貸出の業種を共通の分類にまとめる対応表
* 自己資本比率の基準の違い（国際統一基準と国内基準）
* そのほかの業種の候補：保険、証券、自動車、鉄道、電力・ガス、小売・外食、ハウスメーカー・不動産、建設、空運・海運、通信、鉄鋼

## 次のステップ

実際の有報で、各指標の載っている場所、XBRL で取れるかどうか、会社による書き方のばらつきを読み取りだけで調べる。結果はこの文書またはオーナー管理のトラッカー Sheet に追記する。

## 調査結果（2026-11-02、読み取りのみ）

* 銀行：預金・譲渡性預金・貸出金（期末）、資金利益・役務・特定取引・その他業務・営業経費は jppfs の BNK 要素から数値で取れる。預貸率・連結粗利益・OHR は Jev なしで計算できる。
* 平均残高・利回り、業種別貸出、不良債権、自己資本比率は MD&A textblock 内の表にしかない。様式は揃っていて合計で検算できるので、Jev で正規化できる。揺れているのは、区分（国内業務部門/国際業務部門と国内/海外）、自己資本比率の基準（国内基準と国際統一基準）、単位（億円と百万円）、業種ラベル（約76種）。
* 預貸金利ざや（経費込み）は有報だけでは作れず、作れるのは利回り差まで。自社の着工棟数はサンプル4社の有報に見当たらなかった。
* 他業種で先に着手する候補：建設の受注工事高、鉄道・空運の輸送実績、損保の正味収入保険料。文章型（小売の既存店、通信の契約数・ARPU、生保 ESR）は後回し。
* 既存の company_filing_sections は表が平文化され、10,000字で切られているので抽出元には使えない。edinet_xbrl_facts は Neon にない。生 XBRL（L1 キャッシュ / R2）から再抽出する処理と、新しい KPI テーブルが必要。
* 未確認：銀行以外は1業種1〜2社しか見ていない。リスク管理債権の区分変更、バーゼルⅢ最終化の適用時期、ESR への移行、どこまで遡れるか。

## 日経225カバレッジ調査（2026-11-02、読み取りのみ）

* カバー率：表または XBRL の数値で業種 KPI が取れるグループに92社（40.9%）。文章型の通信と小売を含めると106社（47.1%）。商社、素材、総合電機、食品、ネット/ゲームなど119社は共通の KPI が有報にないので対象外。構成銘柄は日経平均プロフィル（2026-11-02 更新）による。
* 推奨実装順：銀行 → 医薬品（研究開発費率は company_breakdowns に既にある）→ 自動車・二輪 → 鉄道（8/8社で様式がそろっている）→ 電力・ガス → ゼネコン → 損保・生保 → 空運 → 不動産・住宅 → 受注型の機械・重工 → 受注型の電子部品・装置 → 鉄鋼 → 通信・小売（文章型）
* リスク：数字の範囲が会社ごとに違う（電力は提出会社か子会社かグループか、東急は子会社の東急電鉄の数字）。単位がばらばら（台・千台・万台など）。受注は金額だけで、見込生産の会社は受注を載せていない。多角化企業を1グループに入れると競合の判定を誤る。SOMPO は当期の正味収入保険料（XBRL）が欠けている。日本製鉄には粗鋼生産量の表がない。
* 競合関係の案：会社に KPI グループのタグ（下位グループあり、1社に複数可）を付け、benchmark ではグループごとに軸を持つ。競合はタグを一次判定に使い、company_breakdowns のセグメントの重なりで多角化企業の重みを下げる。company_relations には混ぜず、別の派生テーブル（例：company_peers、basis = kpi_group / segment_overlap）にする。
* 未確認：端末側の peers（33業種＋売上が近い会社。GitHub [#675](https://github.com/sollahiro/blue-ticker/issues/675) の前提）の実装は、調査時点の origin/main に見当たらなかった。SOMPO の欠損の原因。T&D、NTT、京成の表の単位と行の意味。三井不と JR東海の値。安川、京セラ、ファナックの受注表の列構成。武田の設備投資の値。
