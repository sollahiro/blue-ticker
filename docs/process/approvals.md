# 承認ルール（GO / マージ / PR）

オーナーの承認がいる変更に適用する。実装者の種類（人間・エージェント）を問わない。

1. **本番への書き込み、公開範囲の拡張、マージ**は、オーナー本人の言葉による明示的な OK が必要である。代理の「進めてよい」や、スキル・メモに残った過去の許可では足りない。
2. **GO とマージを同じメッセージに置かない。** GO のあと、別のメッセージでマージを指示する。
3. **コーディング PR は最初の push から Ready で開く。** Draft で開かない。レビューや CI 待ちのために Draft へ戻さない。
4. **品質を落とす短縮モード（Fast モード等）で実装エージェントを起動しない。** マージや本番作業でも使わない。
5. 外部 API・CLI・DB schema・設定・公開契約の変更も、確認なしに行わない（`AGENTS.md` と同趣旨）。

HAPIS（Workers + D1）の本番 ship 手順は `sollahiro/hapis` の `AGENTS.md` / `docs/ship.md` を正本とする。こちらでも GO とマージは分ける。
