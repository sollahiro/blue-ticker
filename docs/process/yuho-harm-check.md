# 有報と公開面の実害確認

実行者は人間でも、同じ手順を踏むエージェントでもよい。目的は、有報（原本）と公開されている値の食い違い＝**実害**を見つけ、直す材料にすること。

## 何が実害か

期待される値を外しているものは実害である（潜在的な問題より先に扱う）。未取り込みの上場銘柄はバックログであり、取り込み済みなのに空や誤りであるものが実害である。

公開面（REST / 公開 MCP / アプリが表示する値）を正として見る。Neon にしか無いキーだけで「害がない」と判断しない。

## 手順（短い）

1. 対象の有報（PDF / 原本 HTML / XBRL）を開く。
2. 同じ会社・同じ通期について、公開面（`https://api.yuholab.com/v1/` または公開 MCP）の値を取る。認証は `docs/api-auth.md`。
3. 食い違いがあれば、コード・書類・フィールド・期待値と実際の値・出典箇所を記録する。
4. 記録先はオーナー管理のトラッカー Sheet（タブ「実害トラッカー」。必要なら「原文・判断履歴」。URL は `docs/process/tracker-placement.md`）。コード修正が要るときは GitHub Issue を立て、Sheet に URL を残す。
5. テストの golden は、**実害が出た行の正しい答えだけ**足す。網羅的な golden を書かない。

## やってはいけないこと

- 実害を「改善アイデア」や「未取り込みバックログ」と混ぜて一件にまとめる。
- 旧課題管理へコメントして終わりにする（正本は Sheet と、必要なときの GitHub Issue）。
- 面を畳んだカバレッジ報告で「もう埋まっている」と片づける（`coverage-reporting.md`）。
