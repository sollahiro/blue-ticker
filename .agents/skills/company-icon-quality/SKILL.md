# 会社アイコン品質基準

スクリプトは都度生成してよい。ここに書く基準だけは毎回守る。

## 1. 仕上がり
- 512×512 PNG、白背景。透明は白で flatten（アプリは黒地描画なので透明は消える）。
- 中心はキャンバスではなく **中身の外接矩形**（角色との差 > 30 の画素）の中心を合わせる（形による補正は 3）。
- 長辺比 `L = min(0.85, 1/sqrt(1+1/a^2), 0.9375/sqrt(1+1/a^2))`、`a = 長辺/短辺 >= 1`。角まで中身がある正方形（全面塗り・枠つき）は約 66%、横長は最大 85%。
- 配置後、すべての中身画素が中心から 240px 以内（内接円 256 で円クリップしても欠けない）。式で決めたあと、実画素で最大半径を測って超えていれば L を下げる。
- Lanczos で縮小。**マークの長辺は 70% 以上を最低ラインとする**（4 の low_vis と同じ線）。大きいソース（SVG・高解像度 PNG）を先に探し、それでも足りなければ Lanczos で引き伸ばして 70% 以上（目標は 1 の L）にする。原寸のまま 70% 未満で置かない。

## 2. 余白で直す（PAD）
- 長辺 80%、中央、512 白正方形。ただし 1 の 240px 制約を優先する。
- 背景が白以外の全面塗り（色地のロゴ）は、足した余白も **その背景色で塗る**（白枠を付けない）。角色や縁の最頻色をサンプリングする。
- 丸で見て文字の端（最後の一文字など）や角が欠けないことを実画素で確認する。
- 全面塗りの 80% は「タイル（色地ごと）を 80% に縮めた」意味。中身（文字・マーク）の大きさ = 現行の中身比 × 0.8、240px 判定は背景色との差で測る。
- **PAD と塗りつぶしは別**。中身を縮めて余白を足すのが PAD。透明や白地のまわりに色地を足す・塗りつぶす必要がある場合は PAD ではなく NG（理由チップ「余白塗りつぶしが必要」）として作り直す。

## 3. 丸での見え方（視覚補正）
幾何学的に中央・同サイズでも、形によって目にはずれて見える。数値で置いたあと、丸表示で見て次の錯視を補正する。補正後も 240px 制約は必ず守る。
- **位置: 三角形の二等分錯視（見た目の重心）**。三角形を高さのちょうど半分で切ると上側が大きく見え、見た目の中心は幾何学的中点より上に感じる。三角形・L 字・片寄ったマークは外接矩形中心で置くと丸の中で偏って見える。外接矩形中心と面積重心（中身画素の重心。上向き三角なら底辺から高さ 1/3）の間、外接矩形寄りに寄せる。上向き三角は外接矩形中心より少し下げると中央に見える。
- **大きさ: ミュラー・リヤー錯視とオーバーシュート**。同じ長さでも端の形で長短が違って見え、尖った端・丸い端は平らな端より小さく見える。書体で O や A の頂点を基準線から少しはみ出させて揃えるのと同じく、尖ったマークや円形マークは四角いマークと同じ外接枠に入れると小さく見えるので、外接枠を数%（3〜5% 程度）大きくして見た目の大きさを揃える。
- 拡大補正後も横長の 85% 上限は超えない。
- ユーザー指示（「気持ち左上に」等）があればそれに従う。
- 四角では余白なしで良くても丸で欠けるものは、丸基準で直す。

## 4. 差し替え候補（どれか一つ）
計測は正方形への aspect-fit（letterbox）後、背景差 30 の外接矩形で行う。中央クロップで測らない。
- low_vis: マークの長辺 < 70%。
- lockup: マーク＋社名の並びで短辺 < 70% → マークだけを連結成分マスクで切り出す。純ワードマーク（例: 花王、KEIO）は長辺 80–88% なら対象外。
- low_res: **最小辺 < 256px** かつ公式に大きいマーク（apple-touch 180+、header SVG/PNG、OGP）がある。無ければ引き伸ばして 70% 以上にする。

## 5. 中身
- 1社1枚、会社（持株なら本体）のコーポレートマーク。App Icon・製品ブランドは不可。
- 「マークだけでいい」が基本。タグライン（例: 「植物のチカラ」）、「株式会社」表記、「オンラインストア」「Recruiting Site」等の付記は外す。
- 捨てる: SNS ボタン、旧 Twitter マーク、WordPress 既定画像、単色塗りつぶし、ページのスクリーンショット、別法人ホストの画像、ページ部品（toTOP ボタン等）。
- ソースは公式 HTTPS を優先し、必ず実 GET してマジックバイトで確認。SVG は `rsvg-convert`（無ければ `cairosvg`）でラスタ化。公式が小さいときは Wikimedia Commons の SVG、IR 資料 PDF の埋め込み画像、ユーザー提示の URL（楽天・Google サムネ等の第三者でも可）を候補にし、出所を記録する。
- 候補を比べるときはファイル全体ではなく **マーク部分の画素数** で比べる。今より大きくならない候補は採らない。
- favicon が小さくても、ヘッダーのロゴ SVG（インライン SVG 含む）にマークが入っていることが多い。ロックアップから連結成分でマークだけ切り出し、大きくラスタ化する。引き伸ばしより先にこれを探す。
- 白抜きロゴ（暗いヘッダー用）は白地に置くと消える。サイトのヘッダー色で塗り直すか、その色の全面塗りにして、派生と明記する。
- 引き伸ばしが避けられないときは引き伸ばし版を本命にする。ぼやけが強いとき（目安 ×3 超）は注記し、再ソースの余地を伝える。

## 6. 目視チェック（必須）
- 全社、本番に入れる前にユーザーの visual GO を取る（新規も差し替えも）。
- 1社ずつ OK / 余白で直す / NG。NG 理由チップ: 余白が大きい / コンテンツが多い（マークだけでいい）/ 中身が適切ではない / 中心がずれている（丸で見たとき）/ 解像度が低い / **余白塗りつぶしが必要** ＋ 自由記述。URL 欄でソース指定も受ける。
- プレビューは高解像度、中心線と円クリップ表示つき。元・四角／元・丸／余白版・四角／余白版・丸を並べる。プレビュー自体の余白・ずれで判断を誤らせない。
- NG は理由つきで台帳に残し、理由を再ソースに反映する。同じソースを再提出しない。
- **自動合格シート**に載せるのは、正規化 pass かつ **短辺 ≥ 256px** のものだけ。短辺 256 未満や low_res / lockup / low_vis に該当するものは自動合格に入れず、再ソース枠（または通常の差し替えレビュー）へ回す。
